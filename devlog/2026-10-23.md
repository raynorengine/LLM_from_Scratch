## 문제와 해결
- **bash heredoc으로 문서 작성 실패**: 본문에 `'''`·따옴표가 많아 `unexpected EOF while looking for matching '` 발생. Write 도구로 전환해 해결
- **PowerShell/bash 콘솔에 한글이 깨져 출력됨** (`����`): 측정 결과의 한글 예시를 못 읽음 → 결과를 UTF-8 파일로 쓰고 `cat`으로 읽어 해결. 숫자만 필요한 경우는 그대로 둬도 무방

## 하드 검사가 결함 2개를 연달아 잡았다 (이 Phase의 핵심 기록)
"복원 일치율"은 84% 언저리라 합격 기준이 될 수 없어서, **100%여야만 하는 것**을 따로 정했다:
`<S>` 개수 == 원문 공백 개수. 이게 두 번 울렸다.

### 1차: `<S>` 100칸 부족 — Kiwi가 **공백을 품은 토큰**을 만든다
```
`강철 동굴/NNP` (start=2, len=5)   <- 토큰 안에 공백
실측 98개 / 33종: 도망친 로봇(20) 원더풀 데이(9) 존 록스턴(7) 쥘 베른(4) 알파 센타우리(4) ...
```
- 그냥 두면 (1) `<S>` 개수가 모자라고 (2) 복원 때 어절 안 공백을 지우므로 `강철 동굴` → **`강철동굴`** 로 깨진다 (실제로 깨진 것 확인)
- 해결: 공백 든 토큰을 쪼개고 사이에 `<S>` 삽입. `join([('강철','NNP'),('동굴','NNP')]) == '강철 동굴'` 로 복원 결과가 같음을 확인

### 2차: 이번엔 `<S>` 3칸 초과 — Kiwi가 **없던 공백을 만든다**
```
원문 `오토맨`     -> form `오토 맨`      (0칸 -> 1칸)
원문 `칼무크`     -> form `칼 무크`
원문 `아이러브 유` -> form `아이 러브 유`  (1칸 -> 2칸)
```
- form 기준으로 쪼갰더니 원문에 없는 `<S>` 가 생겼다
- 해결: 공백이 끼는 토큰은 **form 을 버리고 원문 조각을 쓴다.** 표준형을 잃지만 98개뿐이고, 원문에 없는 공백을 지어내는 것보다 낫다

# Step7 Phase 3-a (토큰 번호 매기기) — 완료

## 만든 것
- `build.bat` (Step6에서 복사, `DEFAULT_SRC=step7-3a_tokenid`)

## 설계에서 정한 것
- **번호를 사전순 정렬 후 부여** (등장 순서 아님). BOS=0, EOS=1, 실제 토큰은 2번부터
  - 이유: 등장 순서로 매기면 Python 검증기가 **C가 파일을 읽은 순서까지 흉내 내야** 같은 번호가 나온다.
    사전순은 입력 순서와 무관하므로 독립 재계산이 성립한다 (Step6의 코드포인트 오름차순과 같은 이유)
  - 정렬 기준은 `strcmp` = **UTF-8 바이트 순서**. Python 쪽도 `key=lambda s: s.encode("utf-8")` 로 맞춰야 한다.
    파이썬 기본 정렬은 코드포인트 순이라 기준이 어긋나면 번호가 통째로 밀린다
- **`<S>`도 토큰 하나**로 번호를 받는다 (특별 취급 없음)
- arena(큰 덩어리 할당 후 쪼개 쓰기) 사용. `realloc` 으로 늘리지 않는 이유를 주석에 명시:
  주소가 옮겨지면 이미 나눠 준 포인터가 전부 망가진다
- 해시 `2^15`(32,768칸), 적재율 51.6% — Step4의 거부선 70%에 여유

- 출력 형식을 3-c 와 같게 맞춰 **4단계·5단계 프로그램을 고치지 않고 재사용**
  - `step7-4_detokenize.py` 에 출력 경로 인자만 추가 (기존 결과 번호를 덮어쓰지 않도록)

### 시행착오

- **한글 인자가 깨짐** — `어휘에 없는 토큰: ??/NNG`. Windows 가 main 의 argv 를 CP949 로 변환해 준다
  → `CommandLineToArgvW` + `WideCharToMultiByte(CP_UTF8)` 로 명령줄을 다시 받는 `utf8_argv()` 추가 (`#ifdef _WIN32`, `#pragma comment(lib,"shell32.lib")`)
  → 3-c 까지는 인자가 숫자·파일명뿐이라 드러나지 않았던 문제
- **`ᆻ/Z_CODA` 가 어휘에 없음** — `"그는 천천히 고개를 들었"` 처럼 **활용이 끊긴 프롬프트**를 Kiwi 가 종성 조각으로 토큰화
  → 세 번째 실패 유형(문맥 없음 / 어휘 없음)으로 기록. 완결된 `"...들었다"` 로 바꿔 진행
- `write_result` 의 미사용 매개변수로 C4100 → 매개변수 제거 (경고 0 유지)
- Python 스크립트로 C 소스를 고칠 때 `'\0'` 이 실제 NUL 바이트로 들어가 C2137. 바이트 치환으로 복구 (5단계에 이어 2회)

### 5단계 기록의 조건 보정

5단계에서 *"중복이 이미 0이라 7단계 백오프 지표로 쓸 수 없다"* 고 적었다. 그 말은 **프롬프트 없는 생성에 한정**된다.
강의가 백오프를 평가한 조건은 **프롬프트 `돈을` 고정**이고, 그 조건에서 우리도 중복이 **39%** 다.
→ 7단계 평가는 프롬프트 고정 조건에서 중복률 + 복사 비율을 함께 본다.
