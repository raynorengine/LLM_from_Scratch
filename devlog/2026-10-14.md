## 문제와 해결 (삽질 포인트)
1. **CRLF 함정 — 같은 결과인데 `cmp`가 다르다고 나옴**
   - 증상: `cmp step1_char_freq_result.txt step1_char_freq_py_result.txt` → line 1, char 30에서 차이
   - 원인: 이 PC의 `core.autocrlf=true`. 저장소엔 LF(`i/lf`)로 들어 있지만 체크아웃 시 작업본이 CRLF(`w/crlf`)로 변환됨. C 프로그램이 쓴 원본은 LF였다.
   - 해결: 작업본 대신 저장소 blob과 비교 → `git cat-file -p HEAD:<경로> | cmp - <파일>` → 완전 일치
   - 교훈: **git으로 받은 결과 파일과 바이트 비교할 때는 작업본이 아니라 blob과 비교한다.** `git ls-files --eol <파일>`로 i/w 개행 확인 가능
2. **`Path`로 감싸면 결과 파일이 달라짐**
   - Windows에서 `Path("../data/...")`를 문자열로 쓰면 `..\data\...`가 되어 `# input_file` 줄이 C와 달라진다 → 경로는 문자열 그대로 유지
3. **`%-4s` vs `f"{ch:<4}"` 폭 차이**
   - C의 printf 폭은 **바이트** 기준(한글 3바이트 → 공백 1개), Python은 **글자** 기준(공백 3개). 콘솔 출력을 맞추려고 바이트 수로 패딩(`pad_like_c`)
4. Python 3.11에는 `Path.read_text(newline=...)`가 없다(3.13+) → `open(..., newline="")` 사용
5. **Claude 셸에서 `cmd /c "build.bat ..."`가 `'build.bat' is not recognized`로 실패**
   - `cd /d` 후 호출해도 동일. **전체 경로로 호출하면 됨** (`cmd /c "C:\...\PART1_N-Gram\build.bat step1_char_freq"`)
   - vcvars가 내는 `'vswhere.exe' is not recognized` 경고는 무해 (빌드 성공)
