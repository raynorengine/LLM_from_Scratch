- 사용자 요청: 챕터 2-5를 받기 **전에** Claude가 원래 알고 있는 방식으로 바이그램 계획을 세워 보고, 나중에 강의 자료와 비교하겠다고 함

- 모델: P(b|a) = count(a,b) / count(a,·), 단어 안에서만 셈. 단어 경계 토큰 `<S>`(시작)·`<E>`(끝)를 넣음
  - 셀 쌍: 글자 1,551,565 + 단어 420,309 = 1,971,874개 (<S>→첫 글자, 글자→글자, 끝 글자→<E>)
  - 효과: 첫 글자를 따로 뽑는 분포가 생기고, 길이를 고정하지 않아도 <E>가 나오면 단어가 끝남
- 입력: words.txt 직접 (Step1 빈도표에는 쌍 정보가 없음)
- 글자 id: 0xAC00 기준 오프셋(0~11171) → 압축 id(0~2449) 표, +2개 특수 토큰 = V 2,452
- 저장: 2,452² 밀집 배열도 24MB라 불가능하진 않으나 2.79%만 사용 → 희소 구조
  - 세기: 오픈 어드레싱 해시테이블(선형 탐사), 키 = a*V+b
  - 뽑기용: CSR(행 = 앞 글자). 행별 개수 세기 → 누적합으로 row_start → 배치 (계수 정렬, O(n))
  - 행 안 누적 빈도 + upper_bound 이진 탐색 → Step2의 `rand30`/`rand_below`/`sample_index`를 행 범위로 일반화해 재사용
- 생성: <S>에서 시작, <E> 또는 최대 길이까지 반복. 탐욕적(argmax)도 함께 → 반복 루프에 빠지는 것을 보여주기
- 검증(step3_verify.py): Python Counter로 쌍 빈도 독립 재계산 → C `--dump`와 전수 비교 / 행별 경계값 `--map` 전수 / 조건부 샘플 카이제곱 / 생성 단어의 모든 인접 쌍이 학습 데이터에 존재하는지 / 탐욕적 결과 독립 재계산 / `--self-test`
- 강의와 갈릴 것으로 예상되는 지점: 경계 토큰 사용 여부, 단어 경계를 넘어 셀지, 스무딩, 고정 길이 생성 여부, 자료구조(해시 vs 2차원 배열)

### 시행착오
1. **build.bat에서 'vswhere.exe' 메시지가 나옴** → LF 줄바꿈 .bat에서 cmd가 줄을 잘못 읽는 문제를 의심하고 Step4 build.bat을 CRLF로 바꿈 → 그래도 나옴 → Step3 build.bat도 똑같이 냄. vcvars64.bat 내부 메시지이고 빌드에는 영향이 없음. CRLF 변환은 불필요했지만 .bat에는 맞는 형식이라 그대로 둠
2. **bash heredoc 안의 Python으로 C 소스를 치환하다가 깨짐**: `'\n'`이 실제 줄바꿈으로 들어가서 C 문자열 리터럴이 끊겨 컴파일 에러(C2001). 다른 치환은 공백이 맞지 않아 assert에 걸림 → 해당 부분은 Edit 도구로 다시 고침. **교훈: 백슬래시가 있는 C 코드는 heredoc 스크립트로 치환하지 말고 Edit 도구로 고치거나 스크립트 파일(Write)을 실행한다**
3. **seed를 꺼내다 실패해서 바이그램이 seed 0으로 실행됨**: `grep -P`가 Git bash 로케일에서 "supports only unibyte and UTF-8"로 실패 → SEED가 빈 값 → strtoul("") = 0 → step4_bigram_result_01.txt가 seed 0으로 생성됨(트라이그램과 다른 seed). awk로 다시 꺼내 같은 seed로 실행 → **step4_bigram_result_02.txt**. 01은 삭제 규칙(확인 없이 지우지 않음)에 따라 남겨 두고 사용자에게 물어봄. **교훈: 명령을 연결할 때 앞 단계가 빈 값을 내면 멈추게 해야 한다(`[ -n "$SEED" ] &&`)**
