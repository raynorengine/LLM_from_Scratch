# 바이그램 (Bigram)

> 출처: `raw/챕터2-5 바이그램(Bigram).docx` + Claude 보충. 실측값은 `data/korean_dictionary/words.txt` 기준 Python 독립 계산 (2026-10-21)

## 유니그램 → 바이그램
- 유니그램: "어떤 글자가 많이 나오는가" → P(글자)
- 바이그램: "어떤 글자 **다음에** 어떤 글자가 많이 오는가" → **조건부 확률** P(다음 | 앞)
- N-그램에서 n=2. 앞 글자 **1개**만 보고 다음 글자를 예측
- 계산: P(b | a) = count(a, b) / count(a, ·)
  - count(a, ·) = a 뒤에 무언가가 온 모든 횟수 (a로 시작하는 쌍의 총합)
  - 예: '가' 뒤에 쌍이 5번 → 가가 3, 가대 2 → P(가|가)=3/5, P(대|가)=2/5
- 비유: **두 글자 끝말잇기** — 앞 글자를 보고 다음 글자를 고름

## 슬라이딩 윈도우로 바이그램 추출
- 2글자 창을 한 칸씩 이동. 길이 L 단어 → 쌍 L−1개
  - 가가대소: [가가] → [가대] → [대소] (3쌍)
- 강의 예시 (단어 3개)
  | 단어 | 추출된 바이그램 |
  |---|---|
  | 가가 | 가가 |
  | 가가대소 | 가가 가대 대소 |
  | 가가대소하다 | 가가 가대 대소 소하 하다 |
- 빈도 합산: 가가 3 / 가대 2 / 대소 2 / 소하 1 / 하다 1
  - '가' 다음: 가(3) > 대(2) → 가가 확률이 더 높음
- 쌍은 **단어 안에서만** 만든다 (단어 A의 끝 글자 + 단어 B의 첫 글자는 쌍이 아님)
  - 사전은 단어 목록이라 단어 사이에 실제 문맥이 없음
  - (참고) 소설처럼 이어진 글이면 문장 단위로 끊는 것이 같은 원리

## BOS / EOS 토큰
- **BOS** (Begin Of Sequence): 시작 표시 / **EOS** (End Of Sequence): 끝 표시
- 나비 → `[BOS] 나 비 [EOS]` → 쌍 3개: BOS→나, 나→비, 비→EOS
- 배우는 것
  - BOS 행 = **어떤 글자로 시작하기 쉬운가** (첫 글자 분포)
  - X→EOS = **어떤 글자 뒤에서 단어가 끝나기 쉬운가**
- 생성: BOS에서 출발 → 다음 글자 뽑기 반복 → **EOS가 뽑히면 종료**. 길이를 따로 정할 필요 없음 (유니그램은 길이를 고정해야 했음)
- ⚠ 강의 본문의 추출 예시 표(위)는 BOS/EOS 없이 그렸고, BOS/EOS는 [보충]에서 나옴. 강의의 탐욕적 디코딩 결과("사"만 반복)는 **BOS/EOS를 쓴 경우에만** 재현됨 (아래 참고)
- 길이 L 단어 → BOS/EOS 포함 쌍 L+1개

## 자료구조: 해시테이블
- 가능한 쌍: 11,172 × 11,172 = **124,813,584** (강의 "약 1억 2천만" 일치)
- 실측 (words.txt)
  | 항목 | BOS/EOS 없음 | BOS/EOS 포함 |
  |---|---|---|
  | 쌍 총 개수 | 1,131,256 | 1,971,874 |
  | 서로 다른 쌍 | 167,399 | 171,425 |
  - 실제 등장 글자 2,450종 기준으로도 2,450² ≈ 600만 칸 중 2.8%만 사용 → 대부분 0인 표
- 강의 영상 (문서에는 없음, 사용자 전달 2026-10-21): 해시테이블 **또는** 2차원 배열
  - `freq[앞][뒤]` 11,172² × 4B ≈ **500MB** → 너무 큼
  - 실제 사용 2,450자만 인덱싱 → 2,450² × 4B ≈ **24MB** → 적절
  - 원칙: "모든 조합이 글에 존재하지 않는다. 없는 조합에 메모리를 쓰지 않는 것이 중요"
  - Claude 보충: 원칙에는 두 단계가 있음 — 글자 단위(안 쓰는 글자 8,722종 제거 = 압축 인덱싱) / **쌍 단위**(24MB 표도 97.2%가 0 → 해시·CSR로 제거). 2,450² 배열은 첫 단계까지만 적용한 절충안
- **해시테이블**: 키(쌍) → 값(횟수). 해시 함수가 키로 저장 위치를 계산 → 평균 O(1) 조회·갱신
  - Python `dict`/`Counter`가 해시테이블. C에는 없으므로 직접 구현
- C 구현 시 핵심 요소 (Claude 보충)
  - 키를 정수 하나로: `key = a × V + b` (a, b = 글자 id, V = 토큰 종류 수)
  - 해시 함수: 키를 섞어 칸 번호로 (예: 곱셈 해시 후 상위 비트)
  - 충돌 처리: **오픈 어드레싱 + 선형 탐사** — 칸이 차 있으면 다음 칸으로. 빈 칸 = 새 키
  - 크기: 쌍 17만 개 → 2²⁰(≈105만) 칸이면 적재율 16%로 충돌 적음. 2의 거듭제곱이면 `% size` 대신 `& (size−1)`

## 생성 (샘플링)
- 유니그램과 같은 누적 빈도 + 이진 탐색. 차이: **앞 글자마다 별도의 누적 빈도표**
  - 앞 글자 a의 후보들만 모아 누적 → `r ∈ [0, count(a,·))` → upper_bound
- 생성 결과: 유니그램보다 훨씬 그럴듯함. 실제 사전 단어가 나오기도 함 (강의)

## 탐욕적 디코딩의 한계
- 강의: 탐욕적 디코딩 → "사" 한 글자만 반복 출력. 이유는 "사로 시작하는 단어가 사전에서 가장 많아서"
- 실측으로 경로 확인 (BOS/EOS 포함)
  - BOS 다음 1위: **사 4,614** (가 4,448 / 자 4,105 / 고 4,064 / 이 4,060), 전체 420,309
  - 사 다음 1위: **EOS 4,539** (회 583 / 이 438 / 리 425 / 하 419) — '사'로 끝나는 단어가 많음 (변호사, 의사 …)
  - → BOS→사→EOS: 매번 단어 "사"가 생성됨. 탐욕적은 결정적이라 몇 번을 돌려도 같은 "사"
  - 강의 설명은 절반(첫 글자)만 말함. **"사 다음이 EOS"라는 두 번째 조건**까지 맞아야 "사"만 나옴
- 비교: BOS/EOS 없이 '사'에서 출발하면 → 사회로이다리다리다리다… (리→다, 다→리 루프)
- 탐욕적 = 결정적 경로 → 반복/루프. 확률적 샘플링이 필요한 이유 (유니그램과 같은 결론, 바이그램에서 더 극적)
