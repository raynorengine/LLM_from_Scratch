# 유니그램 (Unigram)

## 빈도 → 확률
- 확률 = 글자 빈도 / 전체 글자 빈도 합. 예: 100자 중 '다' 5번 → 5%
- 의미: 국어사전에서 눈 감고 무작위로 한 글자 찍었을 때 그 글자가 나올 확률
- ⚠ 강의 수치 불일치: 강의는 "전체 146만 자, '다' 76,241 / 146만 ≈ 5.2%"
  - 이 저장소 실측(STEP 1, 독립 검증 통과): 전체 **1,551,565자**, '다' **76,241 → 4.91%**
  - '다' 빈도는 일치, 분모만 다름 → 구현·검증 기준값은 **실측값** 사용 (`docs/01_N-Gram.md`도 4.91%)

## 확률적 샘플링 (stochastic sampling)
- 확률표로 글자를 생성할 때 난수 사용 → 확률 높은 글자는 자주, 낮은 글자는 드물게 선택
- 그림: 다(50%) | 하(30%) | 는(20%) 구간을 한 줄로 이어 붙이고 난수가 떨어진 구간의 글자 선택 (난수 63 → 하)
  - ⚠ **가상 예시**(글자 3개, 빈도 합 100). 실제 '다'는 4.91%
  - 구간 길이 = 빈도, 확률 = 구간 길이 ÷ 전체 길이, 누적 빈도 = 구간의 끝 경계

## 누적 빈도 + 이진 탐색 (빠른 샘플링)
- 순차 탐색: 난수가 어느 글자 구간인지 처음부터 비교 → 최악 11,172번
- 누적 빈도 배열을 미리 계산
  | 글자 | 빈도 | 누적 | 난수 범위 |
  |---|---|---|---|
  | 다 | 50 | 50 | 0–49 |
  | 하 | 30 | 80 | 50–79 |
  | 는 | 20 | 100 | 80–99 |
- 난수 r ∈ [0, 전체합) → **누적값 > r 인 첫 글자** 선택
- 누적 배열은 정렬돼 있음 → 이진 탐색: 11,172자도 약 14번 비교 (log₂11172 ≈ 13.4)

## 탐욕적 디코딩 vs 확률적 샘플링
- **탐욕적 디코딩(greedy decoding)**: 항상 최고 확률 글자만 선택 → "다다다다" (반복 문제, repetition problem)
- **확률적 샘플링**: 분포대로 선택 → "다는하다" 등 다양성 확보 + 분포 반영
- 현대 LLM 용어와 동일한 개념

## 유니그램 → 바이그램
- 유니그램: "어떤 글자가 많이 나오는가" (글자 1개 빈도)
- 바이그램: "어떤 글자 **다음에** 어떤 글자가 많이 오는가" (글자 2개 짝)

## [보충] 한글 UTF-8 → 코드포인트
- 한글 11,172자(가 U+AC00 ~ 힣 U+D7A3), UTF-8로 3바이트. C에 3바이트 자료형 없음 → 1바이트씩 읽어 비트 연산으로 int에 합침
- 예: 가 = `0xEA 0xB0 0x80`
  - 1번째 `1110 1010`: 앞 4비트 = 3바이트 문자 표시, 뒤 4비트 데이터
  - 2·3번째 `10xx xxxx`: 앞 2비트 = 연속 바이트 표시, 뒤 6비트 데이터
  - 데이터만 이으면 `1010 110000 000000` = 0xAC00 = 44,032
- (이 저장소에선 STEP 1 `utf8_decode`로 이미 구현)

## [보충] 난수 범위 문제 (MSVC)
- MSVC `rand()`의 `RAND_MAX` = **32,767** → 전체 빈도 합(155만)보다 훨씬 작음 → 이대로는 뒤쪽 글자 선택 불가
- 해결: `rand()` 2개 조합 → 약 10억(2³⁰) 범위 생성
