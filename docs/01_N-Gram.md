# N-Gram (N-그램)

## 한 줄 정의
- N개의 단어(토큰)를 사용하는 언어모델: 입력(앞 n-1개) + 출력(다음 1개) = N개
- 출력은 항상 1개로 고정
- "그램(gram)" = LLM 분야에서 '글자' 또는 '토큰' 단위를 의미

## 언어모델의 기본 동작
- 언어모델은 다음에 올 수 있는 각 단어(토큰)에 확률을 부여 → 가장 높은 확률의 단어 선택
- 예: "철수는 사과를 [?]" → 좋아해(70%) / 먹었다(10%) / 싫어해(20%) 중 선택
- N-gram 구조: 입력(앞 n-1개 단어) → [다음 단어 예측기(빈도표 찾아보기)] → 출력(다음 단어 1개)
  - 예측기 내부는 "입력 단어 → 다음 단어" 빈도표(단어예측표)를 조회하는 것
- 80년 된 기법이지만 아직 쓰이는 이유
  1. 데이터 전처리, 최신 LLM의 반복 억제, RAG 등에 사용
  2. LLM 발전으로 언어모델을 직접 코딩할 필요는 줄었지만, 데이터를 다루는 감각이 중요해짐
  3. 최신 LLM 핵심인 트랜스포머 이해에 도움

## N-gram 공부 순서
유니그램(1-gram, 그램 자체의 빈도) → 바이그램(2-gram, 앞 1그램 보고 다음 예측) → 트라이그램 이상(n-gram, n≥3, 앞 n-1그램 보고 긴 컨텍스트 활용)

---

## 유니그램 (Unigram, 1-gram)
- 한 글자씩 다음 글자를 예측 → 단어 빈도가 아니라 **글자 빈도**
- 국어사전의 모든 단어를 한 글자씩 세어 글자별 등장 확률표 생성
  - 예: 글자 '다' 확률 = 빈도(76,241) / 전체 글자수(1,551,565) ≈ 4.91%
  - 상위 글자: 다(4.91%) > 하(3.10%) > 이 > 기 > 리 > 지 > 사 > 자 > 대 > 수(0.88%)
- 샘플링 방식 비교
  - **확률 우선(탐욕적)**: 항상 최고 빈도 글자만 선택 → "다다다다..." (단어 조합 불가)
  - **확률적 샘플링**: 확률 분포대로 랜덤 선택 → "다는하다" 등 (그나마 그럴듯하지만 의미 없음)
- 한계: 글자가 앞뒤 맥락과 무관하게 독립적으로 뽑히므로 의미 있는 단어/문장 생성 불가

## 바이그램 (Bigram, 2-gram)
- 앞 글자 1개를 보고 다음 글자 1개를 예측 (끝말잇기와 유사한 구조)
- 슬라이딩 윈도우(2글자씩, 한 칸씩 이동)로 글자 쌍 생성
  - 예: '바나나킥' → [바,나], [나,나], [나,킥] (3개 쌍)
- 입력 = 1글자(n-1 = 1), 출력 = 1글자(고정)
- (앞 글자, 다음 글자) 빈도표 예시 ('바나나킥'만 학습 시)
  - 바→나: 1/1=100%, 나→나: 1/2=50%, 나→킥: 1/2=50%
  - prefix 분기 때문에 "바나킥", "바나나킥", "바나나나킥" 등 다양한 길이 생성 가능
- **단어 생성 실험**: 국어사전 전체(약 42만 단어)로 바이그램 학습 → 3만 개 단어 생성
  - 사전에 있는 단어 41%(12,290개) / 사전에 없는 단어 59%(17,710개)
- **문장 생성 실험**: 한국 근대문학+SF번역 코퍼스 (17만 문장, 587만 글자, 1,874종)
  - 공백·구두점도 글자로 취급, 문장 시작/끝에 `<BOS>`/`<EOS>` 토큰 포함
  - 예: "나비는 예쁘다." → `<BOS>` 나 비 는 (공백) 예 쁘 다 . `<EOS>` → 9쌍의 바이그램
  - 자주 등장하는 패턴은 확률이 매우 높음: [하,다] 91.6%(44,128회), [다,`<EOS>`] 93.7%(71,281회)
  - 확률표는 어떤 데이터로 만드는지에 따라 분포가 달라짐 (코퍼스 의존적)
- 한계: 문장이 짧으면 그럴듯하지만 길어질수록 무너짐 — 앞 글자 1개만 보는 구조적 한계

## 트라이그램 (Trigram, 3-gram) 이상
- 슬라이드 크기 3: 앞 글자 2개를 보고 다음 글자 1개 예측
- (앞 2글자, 다음 글자) 빈도표 사용. 예: "나비는 예쁘다." → 문장당 8개 트라이그램 쌍
- 바이그램은 앞 1글자(의미 없는 단위)만 보지만, 트라이그램(n≥3)부터는 앞 2글자 이상 → 의미 있는 단위 포착 가능, n이 클수록 자연스러움
- n을 무한정 늘리면?
  - n이 커질수록 자연스러움 증가 (n=3: 단어만 이어붙인 수준 → n=7: 원본 문체가 느껴짐)
  - 하지만 n이 커질수록 경우의 수 폭증 → 빈도표 크기가 기하급수로 커짐 (데이터 희소성 문제)
  - 그래서 글자 단위로 n을 무작정 늘리기보다, 단어(형태소) 단위로 넘어가는 방법을 사용

## 단어(형태소) 단위의 N-gram
- 한국어는 교착어 → 조사가 계속 붙어서 공백 기준으로 자르면 문제 발생
  - 예: "학교가", "학교를", "학교는" → 공백 분리 시 전부 다른 단어로 인식 → 어휘 폭발
- 해결: 형태소 분석기(예: Kiwi)로 어간과 조사를 분리
  - "학교가" → 학교(명사) + 가(조사) → 공통 어간 "학교"를 하나의 그램으로 처리, 의미 단위 보존
- 글자 단위 → 형태소 단위로 바꾸면 문장이 더 자연스러워짐
- n 증가에 따른 체감 변화 (동일 형태소 코퍼스, 어휘 16,123개 기준)
  - n=2(바이그램): 앞 1단어만 봄 → 단어 나열, 문법 깨짐
  - n=3(트라이그램): 앞 2단어 흐름을 봄 → 짧은 구절은 자연스러움
  - n=4(4-gram): 앞 3단어 흐름을 봄 → 문장 단위로 자연스러움

## N-gram 문장 생성 파이프라인 (3단계)
1. **전처리 (Python)**: 형태소 분석기(Kiwi)로 분리 — 예: "반갑습니다" → "반갑" + "습니다"
2. **생성 (C)**: 토큰 n-gram + 백오프 방식으로 다음 토큰 생성 — 예: "반갑" + "이요"
3. **후처리 (Python)**: Kiwi로 다시 결합 — 예: "반갑" + "이요" → "반가워요"

## 핵심 정리
- N-gram은 앞에 오는 단어(토큰)들로 다음에 올 단어를 예측하는 언어모델
- 실제 데이터의 연속 등장 빈도를 이용해 빈도표(확률표)를 만듦
- 다음에 올 가능성이 있는 모든 단어에 대한 표를 가짐
- 표에 미리 계산된 확률로 다음 단어/글자를 순차적으로 생성
- N이 증가할수록 성능(자연스러움)은 좋아지지만 필요 데이터 수와 메모리 사용량이 급증
- 데이터에 없는 패턴은 전혀 알지 못함 (단순 빈도 카운팅 방식의 한계)
- 데이터에 존재하지 않는 패턴은 문장 생성 자체가 불가능
