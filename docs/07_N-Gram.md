## 핵심 개념: 일반화 vs 암기 (강의 2-7)
- n이 너무 낮으면 패턴이 부족하고(어색함), 너무 높으면 훈련 데이터를 그대로 외운다
- 이것이 N-그램의 근본적인 트레이드오프. NLP 용어로 **일반화(generalization) vs 암기(memorization)**
- 2-6: LLM에서도 같은 문제. 너무 키우면 과적합 = 학습 데이터 그대로 외우는 현상
- 강의 참고 자료: Jurafsky & Martin, SLP3 Ch.3 (스무딩과 일반화). 스무딩은 강의 본문에서 다루지 않음
- Claude 보충: 사전 일치율 하나로는 이 트레이드오프를 다 못 본다
  - 일치율이 높다 = 사전에 있는 단어를 많이 만들었다. "외운 것"과 "잘 만든 것"을 구분하지 못한다
  - 사전에 **없는** 단어(새 단어)가 "그럴듯한지"는 숫자로 재지 못한다 → 생성 단어를 사람이 직접 읽어 판단해야 한다
  - 그래서 결과 파일에 일치율과 함께 **사전에 없는 단어 목록**을 볼 수 있게 남기는 것이 유용하다

## n 일반화 — Step4에서 무엇이 바뀌나
- 문맥 = 앞 **n-1글자**. P(c | 문맥) = count(문맥, c) / count(문맥, ·)
- 패딩: 앞에 BOS **n-1개**, 뒤에 EOS 1개 (Step4 바이그램 1개 / 트라이그램 2개의 일반화)
  - 예 n=4, 단어 "사회": `[BOS BOS BOS 사 회 EOS]` → (BOS,BOS,BOS,사) (BOS,BOS,사,회) (BOS,사,회,EOS)
  - 길이 L 단어 → n그램 **L+1개** (n과 무관) → 전체 n그램 수는 모든 n에서 1,971,874
  - 단어 사이(EOS 다음 BOS들)에 걸친 n그램은 세지 않는다
- 생성: 문맥 (BOS × n-1)에서 출발 → 다음 글자 뽑기 → 문맥 창을 한 칸 밀기 → EOS면 종료
  - Step4는 `prev`, `prev1/prev2` 낱개 변수였다. n이 바뀌면 변수 개수가 바뀌므로 **길이 n-1 배열**로 들어야 한다
- n=2, 3일 때는 Step4 바이그램·트라이그램과 같은 모델이어야 한다 (n그램 집합·빈도가 같아야 함 → 검증 기준으로 쓸 수 있음)

## 자료구조 (Claude 보충 — 강의 문서에는 없음)
- **해시테이블 + 후보 2,452개 순차 조회** (Step4와 동일). **CSR은 쓰지 않는다** (사용자 지시)
- 키 문제: Step4의 정수 키 `문맥 × V + 다음` 은 최댓값이 V^n - 1
  - 2⁶⁴ ≈ 1.8 × 10¹⁹. n ≤ 5는 들어가지만 **n=6은 2.2 × 10²⁰ 으로 넘친다 (약 12배)**
  - 넘치면 서로 다른 n그램이 같은 키로 합쳐지고 오류도 나지 않는다 (Step4 [7] 주석과 같은 문제)
  - 대안 (브리핑에서 결정): 키를 **문맥(64비트) + 다음 글자(int)** 두 칸으로 나눈다
    - 문맥 최댓값 = V^(n-1) - 1. n=6이면 8.9 × 10¹⁶ < 2⁶⁴ → 들어감
    - 한계: n=7은 문맥이 V⁶ 이라 넘친다 → **n ≤ 6** (강의 범위 2~6과 같음)
- 해시 크기: n=6 서로 다른 n그램 1,141,426개
  - 2²¹ 칸이면 적재율 54% / 2²² 칸이면 27% (Step4는 70% 넘으면 거부, 트라이그램은 31%로 운용)
- 뽑기 비용: Step4 실측 해시 조회 1회 ≈ 21ns, 1,000개 생성 361ms (트라이그램). 조회 횟수는 후보 수(2,452)로 정해지고 n과는 무관하다 (해시 크기가 커지면 조회 1회 비용은 달라질 수 있음 — 실측으로 확인)

## 평가: 사전 일치율 (강의 2-6의 방식)
- 1,000개 생성 → `words.txt`에 정확히 있는 단어의 비율. 전체 + 길이별
- n=2~6을 **같은 seed**로 생성해 나란히 비교한다 (Step4의 바이그램 vs 트라이그램 비교를 n 5개로 확장)
- 강의의 n=6 "100% 일치"는 우리 실측으로 확인할 대상이다. 맞지 않아도 구현을 조정하지 않는다
- 탐욕적 디코딩 결과도 n별로 비교할 수 있다 (Step4: n=2 '사', n=3 '사회')
