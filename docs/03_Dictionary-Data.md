# 국어사전 데이터 준비 (챕터2-3)

## AI와 작업 전 사전 작업
- **항상 계획 수립을 먼저 한다.** "그냥 XXX 해줘", "XXX이 뭐야?" 식 지시 → AI가 멋대로 수행
- **"어떻게 해야 해?"로 묻는 이유 (2가지)**
  1. 방법 자체를 묻는 뜻
  2. AI가 앞선 목표 인식(한국어 빈도수 확인)을 **그대로 실행·해결해버리지 않게** 막는 용도
  - 방법이 나열되면 이후 계획·할 일이 보임
- 원하는 형태가 아닐 때 → **원하는 형태의 예시를 보여주면 잘 따라함 (Few-shot)**
- 데이터가 깨지거나 원치 않는 것이 생성될 수 있으므로 **예외처리를 구체적으로 지정**
  - 오염되거나 잘못된 데이터를 직접 보여주고 수정 요청
- **단계마다 내 생각을 말하기 전에 AI가 먼저 다음 계획을 말하게 한다**
  - 다른 사람들의 방법을 학습했으므로 공부에 도움. 단 토큰 사용량 증가
- 공부 관점에서는 AI가 알고 있는 것을 물어보며 진행하는 방식을 권장

|---|---|

## 글자 빈도 계산 = 통계적 언어모델의 시작
- 가장 기본적인 통계적 언어모델 = **N-그램(n-gram)**
- 여기서 "통계" = **각 글자가 몇 번 나타나는지 세는 것**
- 이런 방식을 **카운트 기반 언어모델(count-based language model)** 이라고도 부름
- **글자 빈도(頻度)**: 어떤 현상이 반복되는 정도나 횟수
- 어떤 글자가 더 자주 쓰이는지 알고 싶다면 → 데이터셋에서 **각 글자의 출현 횟수를 세면 된다**

## 글자 카운트 단위 정하기 (음절 / 단어 / 자모)
`'감'`을 예로 들면:

| 단위 | `'감'` 분해 | 전체 종류 |
|---|---|---|
| **음절**(완성 글자) | `감` 1개 | 11,172개 (실사용 2,450개) |
| 자모(초·중·종성) | `ㄱ`,`ㅏ`,`ㅁ` 3개 | 약 67개 |
| 단어 | `감` 1개 | 약 42만 개 |

- 이번 실습은 **음절 단위**로 셈

### 음절과 단어의 차이
- `words.txt`는 **1줄 = 1단어**, 그 단어가 음절 여러 개로 구성
  ```
  가가대소하다          ← 1단어
  가 가 대 소 하 다     ← 6음절
  ```
- 단어 420,309개 ↔ 음절 1,551,565자

### 왜 단어 기준이면 안 되나
- 사전은 **각 표제어가 한 번씩만** 실림 → 단어 기준으로 세면 **전부 1**
  ```
  가가대소하다 → 1번 / 힝힝하다 → 1번 / ... 42만 개 전부 1번
  ```
- 음절 기준이면 같은 글자가 여러 단어에 걸쳐 반복되어 **빈도 차이가 생김**
  ```
  가가대소하다 → 가 2, 대 1, 소 1, 하 1, 다 1
  힝힝하다     → 힝 2, 하 1, 다 1
  합계           하 2, 다 2, 가 2, 힝 2, 대 1, 소 1
  ```
- (애초에 묻는 대상이 "글자"이므로 음절이 맞음)

### 자모 기준을 쓰지 않는 이유
- 조합 종류가 약 67개로 적어 구성 가능한 빈도가 적음
- 유니코드에서 `'감'`은 **한 글자로 저장**되므로 쪼개려면 별도 작업 필요

## 빈도(횟수) → 확률: 확률 기반 언어모델
- 음절 빈도 자체만으로는 의미 없음 → **전체 글자수로 나눠 확률을 구하는 것이 중요**
  ```
  P(글자) = count(글자) / 전체_글자수
  P(다)   = 76,241 / 1,551,565 = 4.91%
  ```
- 알 수 있는 것
  - **모든 확률의 합 = 1** → 이것이 **확률분포**
  - 그대로 **샘플링에 활용 가능**
- **빈도를 파악하는 과정 = 언어모델을 만드는 과정.** 확률표가 곧 모델
- 초기 언어모델에는 **딥러닝 신경망 같은 학습 과정이 없다**

## 결과 해석: `'다'`가 1위인 이유
- 출력: `다(4.91%) > 하(3.10%) > 이 > 기 > 리 > 지 > 사 > 자 > 대 > 수(0.88%) ...`
- 원인: 사전의 **모든 동사·형용사 표제어가 기본형 `'-다'`로 끝남**
  - 예: 가가대소하다, 힝힝거리다, 힝힝대다, 힝힝하다
  - → `'다'`는 동사·형용사 개수만큼 거의 확정적으로 등장
- `'하'`가 2위인 것도 같은 이유 (`'~하다'` 꼴이 많음)

### 착각하지 말 것
- 이 결과는 **"한국어의 글자 빈도"가 아니라 "표준국어대사전 표제어의 글자 빈도"**
- 실제 문장·소설·논문으로 세면 `'이'`, `'는'`, `'을'` 같은 **조사**가 포함됨 (조사는 사전에 거의 안 실림)
- **어떤 데이터를 쓰느냐가 언어모델의 결과를 결정한다**
- 이는 최신 LLM까지 적용되는 원리 — **학습 데이터가 모델의 편향을 만든다**

## 차원의 저주: 배열의 78%가 비어 있다 (예고편)
- `'힣'`을 확인해보니 **한 번도 등장하지 않음**
- 유니코드는 "사용하는 글자"가 아니라 **"조합 가능한 모든 글자"** 를 할당

| | 개수 | 비율 |
|---|---|---|
| 조합 가능 음절 | 11,172 | 100% |
| 사전 등장 O | 2,450 | 21.9% |
| 사전 등장 X | 8,722 | 78.1% |

- 초성 `ㅎ` + 중성 `ㅣ` 뒤에 올 수 있는 종성 28개 중 **실제 사용은 8개**
  ```
  히  3,250     힊  0     힍  0     힑~힗  0
  힘    279     힋  0     힎  0     힚     0
  힐    157     힜  0     힏  0     힞~힣  0
  힌     60
  힝     24
  힙      3
  힉      2
  힛      1
  ```
- `힊`, `힍`, `힑~힗`, `힚`, `힞` 등 20개는 이론상 조합 가능하지만 평생 쓸 일이 없는 글자 → 빈도 0

### 시사점
- **빈도 0 = 확률 0 = 언어모델이 영원히 생성할 수 없음**
- 글자 하나 수준에서는 문제가 아니지만, **앞 글자를 보고 다음을 예측하는 구조에서는 조합 수가 기하급수적으로 증가**
  ```
  글자 1개 조합: 11,172 칸          → 2,450 사용 (21.9%)
  글자 2개 조합: 11,172² = 1.2억 칸  → 극히 일부만 사용
  글자 3개 조합: 11,172³ = 1.4조 칸  → ...
  ```
- 대부분의 조합 확률이 0 → 실질적으로 생성 가능한 조합이 매우 적어짐
- **데이터 희소성(data sparsity)** 문제이며 **N-gram의 근본 한계**

## AI 사용 팁 (추가)
- **계획부터 세우도록 유도**: "바로 해줘" 대신 "어떻게 하면 좋을까"로 물으면 계획을 먼저 제안. 의도를 함께 전달하면 더 적절한 계획이 나옴
- **컨텍스트의 영향**: AI가 C 프로그램을 제안한 것은 앞서 C언어로 Hello World를 진행한 컨텍스트가 남아 있었기 때문
- **AI의 사전 지식**: "빈도"라는 한자 용어를 자연스럽게 이해하는 것은 뉴럴 네트워크 모델이 유사 의미 단어 관계를 파악하기 때문 → NLP에서 **단어 임베딩(word embedding)**
